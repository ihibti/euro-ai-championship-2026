# Brief: Model Equality Testing — Which Model Is This API Serving?

Irena Gao, Percy Liang, Carlos Guestrin. arXiv [2410.20247v2](https://arxiv.org/abs/2410.20247) (ICLR 2025).
PDF: `papers/2410.20247v2_model-equality-testing.pdf` (fetch with `make papers`).

This is one of three organizer reference papers. We do **not** assume it defines the challenge. Sections 1–4 report the authors' work. Section 5b and section 8 are our own assessment and ideas.

## 1. Problem

API providers may quantize, watermark, fine-tune or misconfigure a served model without telling users. The auditor has sample access only. One sample comes from a reference P (local weights, or the API at an earlier date) and one from the API Q, both with the same vocabulary and decoding parameters (§2).

- **What a sample is.** A sample is a pair z = (x, y). The prompt x is drawn from π, which is uniform over m prompts in all experiments. The completion y comes from P(·|x) or Q(·|x) and has at most L tokens. N pairs are drawn per side.
- **Hypotheses.** H0: π(x)P(y|x) = π(x)Q(y|x) against H1: the two distributions differ (Eq. 2).

## 2. Main method (§3)

- **Statistic.** Squared MMD with a unit-norm kernel (Eq. 3).
- **Pooling across prompts.** The kernel `k(z, z') = 1{x = x'} · k̃(y, y')` pools all prompts into one joint test.
- **Estimator (Eq. 4).** `[Σ_PP k + Σ_QQ k] / (N(N−1)) − (2/N²) Σ_PQ k`.
  - The paper does not write out the z ≠ z' exclusion.
  - The released code differs from Eq. 4:
    - it zeroes cross-prompt entries;
    - it cosine-normalises the kernel;
    - it zeroes the diagonals;
    - it divides by the number of same-prompt pairs.
  - The code's statistic is on roughly m× the scale of Eq. 4. The tests themselves are unaffected, because the null distribution uses the same statistic.
- **Kernels studied.**
  - **Hamming (Eq. 7).** `Σ_{i=1..L} 1{y_i = y'_i}`, with the shorter sequence right-padded. It is only a pseudo-metric: it compares per-position marginals (App. A.1).
  - **All-substrings (Eq. 5).** Universal but slow.
  - **One-hot (Eq. 6).** Universal.
  - **Levenshtein (App. C.1).**
  - The paper does not use embedding or neural kernels.
  - **Baselines.** L1 (Eq. 8), χ² (Eq. 9), and approximate goodness-of-fit tests that use log-probabilities (App. C.5).
- **p-values (App. A.2).**
  - **Simulated null (Alg. 1).** Draw both samples from P B = 1000 times and cache the statistics. This is the main-text method.
  - **Permutation (Alg. 2).** Pool the two samples, shuffle and split.
  - **The p-value has no +1 correction:** p = #{T_b ≥ T_obs} / B.
- **Sizes.**
  - N = 10m to 100m. With m = 25, that is 250 to 2,500 samples per side.
  - L = 50 tokens (Wikipedia) or 250 tokens (HumanEval, UltraChat).
  - **Character space.** Used for API audits and when tokenizers differ: decode the text, skip special tokens, and use Unicode code points as the vocabulary.

## 3. Experimental setup

- **Simulations (§4).**
  - π is uniform over 25 random 100-character Wikipedia snippets in 5 languages.
  - Decoding uses temperature 1, with no top-k/top-p.
  - α = 0.05. Power is estimated from 100 simulations over 10 prompt distributions.
  - Models: Mistral-7B-Instruct-v0.3 and Llama-3/3.1 at 8B and 70B. Table 8 adds Phi-3 mini, OLMo 7B and Gemma-2 9B.
- **Distortions tested.**
  - fp16, int8 and nf4 quantization.
  - Kirchenbauer watermark.
  - Fine-tuning Llama-3 8B on 1,000 samples (§4.2).
  - Model swaps across 13 models.
  - Temperature changes (Table 12).
- **Sampling.** 15,000 completions per prompt for fp32 and 5,000 per prompt for the other local variants. GPU-hours are not reported.
- **API audit (§5).**
  - 31 endpoints from 9 providers, collected July–August 2024.
  - Character space, α = 0.01, N = 10m.
  - Composite null: reject only if both p₁ < α and p₂ < α, where the two tests use the fp32 and fp16 references (Eqs. 10–11).
  - Each test is repeated 10 times. An endpoint fails if its mean rejection rate is ≥ 0.5.

## 4. Authors' findings (quoted from the paper)

- **Headline result.** Hamming MMD reaches a median power of 77.4% across alternatives with about 10 samples per prompt. This is the best of the tests compared (Abstract, Fig. 2).
- **Where it is weak and strong.** Power is weak against fp16 (Fig. 2, Fig. 5). It is the most robust test as L grows.
- **Fine-tuning.** Detected with more than 50% power after a single epoch (Fig. 3).
- **More samples help.** For Llama-3 8B, going from N = 10m to N = 50m raises watermark/nf4/int8 power from 0.62/0.38/0.30 to 1.00/1.00/0.96 (Table 11).
- **Type-I error is controlled.** Empirical FPR at α = 0.05 is 0.04–0.07 (Table 8).
- **Audit outcome.**
  - 11 of 31 endpoints serve a distribution different from the reference (Fig. 1, Table 16).
  - Each audit costs at most $0.93 (§5).
- **Inconsistencies in the paper.**
  - Eq. 4 omits the diagonal exclusion.
  - The dataset size is reported as 1M, 1.1M and 1.6M in different places.
  - The 70B Bonferroni powers in Table 17 exceed the single-distribution powers in Table 15, which a stricter α should not produce.

## 5. Practical limitations

**(a) Stated by the authors**

- Hamming is a pseudo-metric and cannot detect fp16 changes.
- The simulated null requires heavy sampling from P.
- The composite decision rule is pessimistic.
- Working in character space reduces power.
- APIs drift over time, and chat templates must match exactly.
- The test measures the size of a change, not whether quality went up or down.

**(b) Our assessment**

- **Setup mismatch looks like distortion.** Any mismatch reads as a distortion: top_p, system prompt, chat template, stop sequences, whitespace or Unicode normalisation.
- **Shifts break Hamming.** Because Hamming compares position by position, a single-token shift destroys similarity.
- **Length leaks into the kernel.** The code counts PAD == PAD as a match.
- **Local inference is required.** Building the reference needs the full model at matched precision.
- **Bugs in the official code.**
  - The vectorised kernel allocates N×N×L booleans, about 6 GB at N = 2,500 and L = 1,000.
  - Its memory-saving branch writes a symmetric copy into a cross-kernel matrix. That is incorrect, and it fails when the two sample sizes differ.
- **Paid APIs.** We assume no paid API usage in the hackathon.

## 7. Reusable, task-independent components

1. **Encode and pad.**
   - Encode completions as integer sequences: token IDs, or code points via `ord(c)`.
   - Truncate to L and right-pad with PAD = −1.
   - In token space, everything after EOS becomes PAD.
   - Implemented in `euroai.kernels.encode_unicode` and `euroai.kernels.pad_truncate`.
2. **Prompt-aware Hamming Gram matrix (code behaviour).**
   - `K[a,b] = 1{x_a = x_b} · (1/L) Σ_i 1{Y[a,i] = Y[b,i]}`, where PAD == PAD counts as a match.
   - Memory is O(N²): the implementation accumulates over positions.
   - Implemented in `euroai.kernels.prompt_hamming_gram`.
3. **MMD² estimator.**
   - The unbiased U-statistic generalises Eq. 4 to unequal sizes (App. C.6).
   - Implemented in `euroai.stats.mmd2_unbiased` and `euroai.stats.mmd_permutation_test`. The pooled Gram matrix is computed once and then permuted.
4. **Permutation p-value.**
   - We use `(1 + #{T_b ≥ T}) / (1 + B)`, which is exactly valid. The paper uses `#/B`.
   - Implemented in `euroai.stats.permutation_pvalue`.
5. **Simulated-null p-value (Alg. 1).** Cache the statistics computed on pairs drawn from a reference pool.
6. **Power and FPR estimation.** Power is the mean of `1{p_s < α}` over S trials. FPR is the same quantity with Q = P. The Monte Carlo standard error is `√(p̂(1 − p̂)/S)`.
7. **Audit decision rules.** The composite AND rule (Eq. 11), Bonferroni correction, and the rule "fail if the mean rejection rate is ≥ 0.5".

## 8. Hackathon experiment ideas (ours, not the authors')

All of these use small open models run locally with vLLM or HF transformers. No paid APIs.

1. **Inference-stack sensitivity map.**
   - Take a 0.5–3B instruct model with an HF reference. Compare it against vLLM at the same dtype, fp16, int8/nf4, AWQ/GPTQ/fp8, fp8 KV-cache, top_p = 0.95, and template variants.
   - Metric: power and FPR.
   - Risk: HF and vLLM may already differ at the same dtype.
2. **Alignment-robust kernels.** Position-decayed Hamming, a small-k spectrum kernel, and a prefix-match kernel.
   - Risk: picking the kernel on the evaluation pairs leaks into the result.
3. **White-box feature test.** Run a permutation test on log-likelihoods under P.
   - Risk: re-tokenising decoded text may not reproduce the original tokens.
4. **Sequential auditing.** Use e-values or early stopping, and measure the expected number of samples needed to reject at matched FPR.
   - Risk: naive repeated testing inflates the FPR.
5. **Variant identification.** Classify which configuration produced a sample, using the nearest reference by MMD.
   - Risk: near-identical variants cap the achievable accuracy.
